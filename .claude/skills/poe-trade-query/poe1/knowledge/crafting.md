# 工藝詞綴（craft bench）— 壓低配裝成本的關鍵

## 核心技巧（使用者教，2026-07-28）

**買「空 1 條後綴」或「已有 1 條工藝後綴」的裝備，抗性自己打上去。**
這種裝備賣相差，所以**明顯比較便宜**——但買回來補一條工藝抗性後，實戰數值可能追平甚至超過
那些原生詞綴齊全的貴貨。這是**降低成本**的手段，不是拉高上限的手段。

前提與規則：

- **抗性詞綴只會出現在後綴（suffix）。** 所以只有後綴的空位才有意義，前綴空著不影響抗性。
- **上工藝的成本幾乎為零**，而且**抹掉舊工藝、換上新的可以無限次重複**。
- **roll 值雖然浮動，但因為能無限重試到滿意為止，估值時直接假設吃到該階最高 roll。**
- **只有未腐化（uncorrupted）的裝備能做工藝。** 腐化裝一律視為沒有工藝空間。
- **Mirrored（複製品）一律不能做任何工藝**——見下一節，這是獨立於腐化的第二道封印。

## ⛔ Mirrored（複製品）：第二種「永久定型」，而且 API 欄位名不叫 mirrored

（使用者教 2026-08-02，當場實測佐證）

**被標記為 Mirrored 的裝備永遠定型，任何手段都不能再改動它**——不能上工藝、不能洗、什麼都不行。
這與腐化是**兩個獨立條件**，只檢查 `corrupted` 會漏掉一整類物品。

- **fetch 回傳的欄位是 `item.duplicated: true`，不是 `item.mirrored`。** 搜尋端才叫
  `misc_filters.mirrored`（`{"option":"true"/"false"}`）。**兩邊名字不一樣，很容易只做對一半。**
- **在架量（2026-08-02，全聯盟稀有裝）：戒指 5587、腰帶 274、手套 211、頭盔 179。**
  **戒指是重災區**，與使用者說的「通常出現在戒指或項鍊」一致。做戒指池時務必處理。

### Mirrored 常伴隨「鏡池（Reflecting Mist）」隱性，會改變詞綴格數與正負

實測樣本（一隻 1 divine 的 Manifold Ring）：

```
+1 Prefix Modifier allowed              ← 前綴變 4 格
-2 Suffix Modifiers allowed             ← 後綴只剩 1 格！
Implicit Modifiers Cannot Be Changed
50% increased Prefix Modifier magnitudes ← 這才是它有 +266 生命 / +90 ES 的原因
-33% to Global Critical Strike Multiplier
-12 to Evasion Rating
```

兩個推論，都會讓天真的估值出錯：

1. **「稀有裝有 3 個後綴」這個假設會壞掉。** 要解析 `[+-]# (Prefix|Suffix) Modifiers? allowed`
   把上限算出來，再拿 native 後綴數去比。上面這隻的上限是 **1**、已用 1 ⇒ **零空位**，
   但只看「native 後綴 ≤ 2」會誤判成可以再上一條抗性工藝。
2. **極端數值的代價是負面詞綴。** 這類物品常帶 `-33% 全域暴擊加成` 這種硬傷，
   **能不能接受完全取決於流派**，不能一律當成好貨。

## ⚠ 負面詞綴：抗性正則寫死 `\+` 會把懲罰讀成 0（2026-08-02 踩到）

快取的 3963 件裡有 **229 件帶負面詞綴**（戒指 220、手套 9），其中包含
**`-60% to Lightning Resistance`、`-58% to Lightning Resistance`**。

用 `\+(\d+)% to Lightning Resistance` 這種**寫死正號**的正則去解析，這些會match 不到而算成 **0**，
於是整組的雷抗被**高估最多 60 點**——直接產生「看起來達標、實際破防」的組合。
**所有數值正則的捕捉群都要寫成 `([+-]\d+)`**，交給 `int()` 處理正負號。

### 負面詞綴要分三類，只有第三類該問使用者（使用者指示 2026-08-02）

> 「並不是所有負面詞都是不可以接受的，根據流派不同某些負面詞是可以無視的。
> 所以你依然可以把持有負面詞的裝備納入考量，或者是在樣本採集完成之後可以把
> 幾個你覺得可能會影響到流派運作的負面詞 pickup 出來詢問使用者。」

| 類別 | 判斷方式 | 處置 |
|---|---|---|
| **modelled** 已納入計算 | 該詞綴文字能被評分／約束的正則吃到 | **不准禁**。懲罰已經算進分數與抗性了，禁掉只是白白少選項——一件 `-60% 雷抗` 但夠便宜、其他部位補得回來的裝，仍然可能是最佳解的一部分 |
| **structural** 只改物品結構 | `# Prefix/Suffix Modifiers allowed`、`to maximum Sockets`、`Implicit Modifiers Cannot Be Changed` | 不影響角色強度。詞綴格數那幾條要餵給後綴上限計算 |
| **unmodelled** 其餘 | 兩者皆非 | **列出來問使用者**，效果無法從目標函數推得 |

`gear_combo_es_poe1.py negatives` 子命令就是做這件事：撈完池子後把樣本裡的負面詞綴
按上表分類、附上件數與部位分佈印出來。實測（3963 件樣本）分別是 12／10／5 種。

⚠ **分類器有極限，要人眼複核**：`-# Lightning Damage taken from Hits` 開頭是減號，
但它其實是**減傷、是好事**，會被誤放進待判斷清單。「減號開頭」只是啟發式，不是語義判斷。

### ⛔ 黑名單是「綁流派」的，不是通則——每次配裝都要重新問

**使用者明確要求（2026-08-02）**：
> 「現在制定的黑名單只適用於這次的我現在這個流派，今後如果有其他流派要配裝的話依然要重新詢問。」

所以：

- **這份知識庫不記錄任何具體的黑名單內容**（記了就會被下次沿用，那正是要避免的事）。
- 黑名單存在 `scripts/gear_pools_poe1_es/banned_mods.json`，**跟池子放在一起**——
  新的請求開新的 WORKDIR，清單自然是空的。
- **程式預設空清單**，絕不自己決定要禁什麼。
- 同一條詞綴在不同流派的意義完全相反：`-#% 暴擊加成` 對暴擊流是致命傷、對異常狀態流無感；
  `-# 智慧` 對 ES 流是實質損失（int 給 %增加 ES）、對力量流無關痛癢。

## 三類抗性工藝的上限（依部位）

| 部位 | 單元素 | 雙元素複合 | 元素＋混沌複合 |
|---|--:|--:|--:|
| 手套、鞋子、胸甲、頭盔、腰帶 | **+35%** | **+20%**（各） | **+15%**（元素側） |
| 項鍊、戒指 | **+28%** | **+16%**（各） | **+15%**（元素側） |

- 單元素例：`+(29—35)% to Cold Resistance`
- 雙元素例：`+(17—20)% to Fire and Cold Resistances`（**兩種元素各 +20，總抗性點數 40**）
- 元素混沌例：`+(13—15)% to Lightning and Chaos Resistances`（**pseudo 三抗只計元素那一半**）

**雙元素複合在「總抗性點數」上其實最划算**（20+20 = 40 > 單元素 35），
但如果缺口集中在單一元素（例如只缺火），單元素 35 才是對的選擇。**選哪一種要看缺口分佈，
這正好是聯合求解器該決定的事**，不要預設。

## 項鍊／戒指通常不這樣做（使用者提醒）

兩個原因：**能上的抗性數值較差**（28/16 vs 35/20），而且**這兩個部位的工藝欄位通常留給更值錢的
特殊工藝**。所以實務上這招主要用在 **頭盔／手套／鞋子／胸甲／腰帶**。

## ✅ 正解：在**搜尋階段**就用 pseudo 過濾掉（使用者教，2026-07-28 實測）

**這是首選做法**，比抓回來再逐件解析好得多——池子回來就只剩可工藝的貨，不浪費 fetch 配額，
而且「空幾條後綴」是**站台自己算的**，不是我們從詞綴反推。

用一個 **`count` 群組**把「空後綴」與「已有工藝後綴」當成 OR 條件（滿足其一即可）：

```jsonc
"stats": [
  { "type": "and", "filters": [
      { "id": "pseudo.pseudo_total_life", "value": {"min": 150}, "disabled": false } ] },
  // 「至少滿足下列 1 條」= 有空後綴位，或有一條可抹掉重上的工藝後綴
  { "type": "count", "value": {"min": 1}, "filters": [
      { "id": "pseudo.pseudo_number_of_empty_suffix_mods",   "value": {"min": 1}, "disabled": false },
      { "id": "pseudo.pseudo_number_of_crafted_suffix_mods", "value": {"min": 1}, "disabled": false } ] }
],
"filters": {
  "misc_filters": { "filters": { "corrupted": {"option": "false"} } }   // ← 必加，腐化裝不能工藝
}
```

相關的 pseudo id（`../references/stats.tsv` 實查）：

| id | 顯示文字 |
|---|---|
| `pseudo.pseudo_number_of_empty_suffix_mods` | `# Empty Suffix Modifiers` |
| `pseudo.pseudo_number_of_crafted_suffix_mods` | `# Crafted Suffix Modifiers` |
| `pseudo.pseudo_number_of_empty_prefix_mods` | `# Empty Prefix Modifiers` |
| `pseudo.pseudo_number_of_empty_affix_mods` | `# Empty Modifiers` |
| `pseudo.pseudo_number_of_crafted_mods` | `# Crafted Modifiers` |
| `pseudo.pseudo_number_of_prefix_mods` / `..._suffix_mods` | `# Prefix / Suffix Modifiers` |

**實測（2026-07-28）**：上面這個查詢**回 200，`count` 群組沒有撞複雜度上限**
（與 `weight`/`weight2` 不同，那兩個即使只放一條也會被拒——見 [../QUERY.md](../QUERY.md)）。
`L150 + 未腐化 + count(空後綴|工藝後綴)` 的頭盔在架 **5042 件**，供給非常充足。
撈回前 5 件用下面的 tier 數法交叉驗證，**5/5 都是原生後綴 ≤2，與過濾器完全一致**。

**價格佐證**：那 5 件 L150+ 頭盔的價格是 **2 alch（≈0.14c）／5 alch／1 chaos ×3**——
「賣相差所以便宜」在數字上非常明顯，這正是這招的價值所在。

### ⚠ 估值時別把已有的工藝重複計算

若物件**已經有一條工藝抗性後綴**，它現在顯示的抗性**已經含那條工藝**。既然要抹掉重上，
正確算法是：

```
effective_res = (現有抗性 − 已存在的工藝抗性) + 該部位最佳工藝值
```

辨識現有工藝靠 `flags.crafted` / `domain == "crafted"`（見 [../QUERY.md](../QUERY.md)）。
**只用 count 過濾器是看不出這件事的**，所以解析階段仍然要標記哪幾條是工藝詞綴。

## 備援：從 fetch 回傳自己判斷後綴空位（2026-07-28 實測）

**可以精確判斷。** fetch 回傳的每條詞綴物件裡，`mods[].tier` 的**開頭字母就是詞綴類型**：

- `P1` / `P2` / `P8` … = **前綴（prefix）**
- `S3` / `S6` / `S9` … = **後綴（suffix）**

⚠ **一條顯示文字可能由多條詞綴合成**，所以**要數不重複的 `(name, tier)`，不能數顯示行數**。
實測樣本：

```jsonc
{ "description": "+167 to maximum Life",
  "mods": [ {"name": "Urchin's", "tier": "P2"},    // 複合前綴（同時給護甲）
            {"name": "Fecund",   "tier": "P1"} ] } // 純生命前綴
// "Urchin's" 也出現在 '+33 to Armour' 那一行 —— 同一條詞綴、兩行顯示
```

判斷式（稀有裝前綴 3 條、後綴 3 條上限）：

```
native_suffixes = 不重複 (name, tier) 中 tier 以 'S' 開頭、且非 crafted 的數量
可上抗性工藝  ⟺  未腐化 且 native_suffixes <= 2
```

工藝詞綴的辨識（見 [../QUERY.md](../QUERY.md) 的詞綴回傳格式）：`flags.crafted` 或
`domain == "crafted"`，且 hash 走 `crafted.` 命名空間。**已有的工藝後綴是可以抹掉重上的**，
所以它佔的那格要算成「可用」而不是「已滿」。

實測四頂高血頭盔的後綴佔用：Royal Burgonet 1 條（**空 2 格**）、Samnite Helmet 3 條、
Praetor Crown 3 條（前後綴全滿）、Pig-Faced Bascinet 3 條。**空位是有的，但不是多數**，
所以值得當成搜尋條件而不是碰運氣。

## 已實作＋實測效益（2026-07-28）

[`../../scripts/gear_combo_optimizer_poe1.py`](../../scripts/gear_combo_optimizer_poe1.py)
已支援工藝：可工藝的候選會**展開成多個虛擬候選**（火+35／冰+35／雷+35／火冰+20／火雷+20／冰雷+20，
飾品用 28/16），由求解器自己挑補哪一種；`POE_CRAFT=0` 可關掉做對照。

**同一份市場快照的 A/B**（六部位、F129/C62/L91、三抗各留 +5 緩衝、`POE_FAST=75`）：

| 預算 | 不工藝 | 含工藝 | 差 |
|---|--:|--:|--:|
| 8c | 953 | **982** | +29 |
| 10c | 967 | **989** | +22 |
| 12c | 972 | **993** | +21 |
| 15c | 985 | **994** | +9 |
| 20c | 993 | **1003** | +10 |
| 30c | 997 | **1005** | +8 |

**真正的價值是省預算，不是拉高上限**（與使用者的說法一致）：

- 不工藝要 **20c** 才到 993 血；含工藝 **12c** 就到 → **省 40%**。
- 不工藝花滿 30c 得到 997；含工藝 **約 18–20c** 就追平 → **省 10–12c**。
- **預算越小，效益越大**（8c 時 +29 血，30c 時只剩 +8）——高預算本來就買得起原生抗性，
  工藝是在錢不夠時替代掉那筆花費。

候選中約 **41%** 可工藝（1078 件裡 444 件），展開後約 3742 個虛擬候選。

### ⚠ 實作時踩到的坑：瘦身必須在展開「之前」

第一版先展開再 `thin()`，結果**含工藝的答案比不工藝還低**——這在邏輯上不可能
（含工藝的候選集是不工藝的超集）。原因是展開讓每件變成約 7 個變體，
把 `thin()` 的名額吃光，留下的是「少數幾件的各種工藝變體」而不是多樣的物件。
**正確順序：pareto → thin（對實體物件）→ 展開工藝。**

另外兩個必要修正：

- **`pareto()` 要把「工藝潛力」當成第五個軸**，否則一件腐化／後綴滿的物件會把
  可工藝的物件剪掉——但後者多了最高 +35 抗的空間。
- **`thin()` 要額外保留「可工藝的領先者」**：這些物件的身上抗性低是**設計如此**，
  在所有既有排序裡都墊底，不特別撈就會被丟光。
